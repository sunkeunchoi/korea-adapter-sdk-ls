Grounding Context

Codebase Context. The strategy finder is the iterative research loop in adapters/nautilus/lab: agent-run turns propose a lever (parameter or mechanism change to the opening-range-breakout strategy), backtest it offline via the lab-research binary, apply statistical gates, and record KEEP / REVERT / FALSIFIED verdicts. Head is v30 (ratio-ATR budget tilt, RoR 0.1262), reached over 13+ turns from v3.

  • Experience capture today: an 827-line prose TURN-LOG.md, frozen PRE-REGISTER docs in data/turn4-fresh/, plan docs, docs/solutions entries, and agent memory topic files. Every merit-bearing turn already follows the same 8-part template (verdict, Phase A, Phase B, bind check, edge gate, mechanism read, registry state, R6 queue re-rank) — but no structured gate-outcome matrix, no coded failure reasons, no cumulative trial count, no lineage graph.
  • Gates today: Phase-A (collinearity |r|<0.70, materiality) is entirely manual — frozen python scripts run via uv run --with pyarrow, twin-verified by eye, thresholds hand-copied between script and PRE-REGISTER. Phase-B strict-KEEP (RoR, dominance ≤0.40) is automated in the runner. The forbidden-overfit rule ("never soften a threshold after seeing the value") is enforced by convention only.
  • Skill layer today: ten frozen .agents/skills/ recipes with machine-readable verdict lines and a proven orchestrator/fresh-context-worker pattern — all for the TR lifecycle, zero for the strategy loop.
  • Verified live defect: the agent memory index simultaneously carries "head v26" and "HEAD IS NOW v30, not v26" today; TODO.OFFLINE.md shows the same staleness pattern ("family closed" written the day the family reopened).
  • Institutional learnings applied: approximate reads get falsified by reconciled runs (turn 10); a teacher/preview layer must call the decider's bound functions, never re-derive gate logic (anchor-mismatch bug); the runner has no version-only-bump path (open seam, 2026-07-15); green runs do not validate default-off lever paths; the 0.5 proposal-bounds cap and seed assertion must never be bypassed by automation.
  • External context: Voyager skill libraries, Reflexion, ACE (Generator/Reflector/Curator, grow-and-refine deltas, arXiv 2510.04618), GEPA Pareto frontiers, AlphaEvolve program databases, SkillOps skill-rot, Agent KB teacher/student separation; from quant practice, the Deflated Sharpe Ratio and CSCV/PBO (Bailey & López de Prado) — the missing datum in iterated backtests is the number of trials, and the repo's gates are per-lever, not queue-cumulative.

Machine turn substrate: turns.jsonl + HEAD-STATE.yaml, prose becomes a projection

axis: turn-capture-reflection Confidence 85% Complexity Medium

Description: Invert the record. The runner's verdict step emits one structured record per turn — verdict, each gate reading against its frozen threshold, bind counts (predicted vs observed), lineage edge (which head it flipped off), lever family/class status, and a coded failure mechanism for non-KEEPs (INVERTED-SIGNAL, COLLINEAR, COVERAGE-CULL, WINNER-CUTTING, RoR-NEGATIVE-RESHAPE) — into a committed turns.jsonl. A single atomic HEAD-STATE.yaml (head version, hash, RoR, armed params, kept levers, spent classes, trial count) is updated in the same step. TURN-LOG prose and memory lines become projections of the record, with a docs-check-style assertion that they agree — exactly how ls-docgen + make docs-check already keep docs/reference/ honest. A curated priors section ("dimensionless ratios escape price-scale collinearity") lives in the same substrate, edited by grow-and-refine deltas.

Basis
direct: dossier gaps verified against the repo — "no structured gate-outcome matrix… falsification reasons narrative, not tabular"; the verifier independently confirmed the live head-pointer contradiction in MEMORY.md (a stale "head v26" line coexisting with "HEAD IS NOW v30") and found the same staleness pattern in TODO.OFFLINE.md:8. Repo precedent: ls-docgen projection + make docs-check. external: ACE's Curator role and its named failure modes (brevity bias, context collapse); the curated-memory-beats-append-only finding.
Rationale
This is the Level-1/2 foundation everything else consumes: trial accounting (idea 2), calibration scoring (idea 7), a replay benchmark, and any future teacher agent all need a queryable record instead of 827 lines of prose. And the head-pointer contradiction is not hypothetical — a fresh agent session seeding a turn from the wrong baseline is exactly the bug class the RVOL turn already had to dodge by hand ("Seed from v16, NOT the registry head").
Downsides
Schema design deserves care (cause-code taxonomy especially) or it fragments into competing ledgers; back-filling 13 historical turns is real but bounded work; the projection gate adds one more assertion to the commit gate. Quick first step that stands alone: ship HEAD-STATE.yaml and fix the contradiction today.

Cumulative TRIALS ledger + a deflating KEEP bar

axis: lever-queue-meta Confidence 70% Complexity Medium

Description: Track what quant practice says is the one datum an iterated backtest must never lose: how many shots have been taken. An append-only TRIALS.jsonl records every gate reading, flip, and sweep leg (family, sample fingerprint, verdict). A frozen script — same idiom as the Phase-A gates — derives a deflated KEEP margin: the strict-improvement floor rises as cumulative trials on the same sample grow (Deflated-Sharpe / alpha-spending style), with a periodic CSCV/PBO audit over the archived legs.

Basis
direct: "The TURN-LOG and plans do NOT record a cumulative 'N trials / N families / N spent' ledger across all turns" (lever-queue evidence, verified); v30 margin "+0.0091, strict PASS" verified at TURN-LOG.md:49. external: Bailey & López de Prado, Deflated Sharpe Ratio and CSCV/PBO — overfit strategies from iterated backtests don't merely fail to outperform live, they systematically lose.
Rationale
Every per-lever gate is locally sound; the multiple-comparison problem lives between them, and it compounds silently with each turn. This is the one idea that could change a past verdict — and every other idea here raises turn throughput, which makes the correction more urgent, not less. It should land before the loop gets faster.
Downsides
Naive DSR assumes roughly independent trials; this loop's trials are sequential and conditioned on prior outcomes, so the correction needs honest adaptation (the verifier flagged this) — treat the first version as a conservative audit, not a precise p-value. May deliver unwelcome news about v30's margin.

run-strategy-turn: the eleventh frozen skill, aviation-checklist style

axis: skill-recipe-layer Confidence 80% Complexity Medium

Description: Mint .agents/skills/run-strategy-turn/SKILL.md on the contract the TR lifecycle already proved ten times: input via $ARGUMENTS (one pre-register path), non-interactive, state-driven, single machine-readable last line (KEEP v<N> <hash> / REVERT <cause-code> / PREDICTED-INERT / HELD <reason>). Its preflight is an aviation-style checklist where every line cites the incident that created it: stale-binary strings check, EXPECT_VERSION seed assertion, build-from-adapters/nautilus rule, companion-field seeding (the v30 gotcha), archive-before-analyze. Standing rule: every new strategy-loop docs/solutions/workflow-issues/ entry must land a checklist line in the same PR — the incident-report-to-checklist pipeline, institutionalized. The machine-readable verdict makes turns orchestratable later with the existing promote-trs → tr-promoter dispatch machinery, unchanged.

Basis
direct: verified — ten skills exist in .agents/skills/, none touch the strategy loop; the 8-part turn template (verdict, Phase A, Phase B, bind, edge gate, mechanism read, registry state, R6 re-rank) repeats across 13+ TURN-LOG entries; the stale-binary gotcha appears verbatim in two memory entries three days apart. external: aviation checklists / ASRS incident databases; Voyager's validate-before-library-add.
Rationale
This is the repo's own theory of learning — repeated procedure → frozen recipe → orchestratable skill — never applied to its most-repeated procedure. Thirteen turns is more repetitions than track-tr had when it was frozen. It is the Level-2→3 move the supplied framework names, executed as a precedent transplant rather than an invention.
Downsides
A frozen recipe can ossify while the loop is still evolving (this is what ideas 1 and the replay corpus mitigate — version the skill, benchmark changes against archived verdicts); authoring the checklist well requires mining the gotcha history once, honestly.

Mechanized Phase-A: turn diagnose + GO-artifact guardrail + freeze-by-git

axis: gate-mechanization Confidence 65% Complexity High

Description: Make the loop's constitutional rule — "never soften a threshold after seeing the value" — structurally unbreakable instead of honor-enforced. One machine-readable PRE-REGISTER (thresholds live in exactly one place); a lab-research turn diagnose subcommand runs the gate script and its independent twin, bit-compares them, checks readings against the frozen thresholds, and writes a gate-verdict.json (GO/STOP + readings + the pre-register's git blob hash). A second guardrail — the existing IntentGuardrail trait, same idiom as the proven 0.5 proposal-bounds cap — makes Phase-B turn() refuse any flip that lacks a matching GO artifact. Git commit ordering proves the freeze predates the reading.

Basis
direct: "Operator must: 1. manually run uv run --with pyarrow… 2. manually run the twin 3. hand-compare bit-for-bit 4. decide manually" and "no runner validation prevents re-reading a gate with a softened threshold" (gate evidence, verified); thresholds duplicated between ratio_atr_tilt.py constants and the PRE-REGISTER prose (verified); IntentGuardrail + PROPOSAL_BOUNDS_CAP=0.5 wiring verified at research.rs. external: GLP witnessed lab notebooks / 21 CFR Part 11 audit trails.
Rationale
Every idea that delegates more of the loop to agents is unsafe while the forbidden-overfit rule is convention-only. This converts the loop's strongest convention into its strongest invariant — the precondition for unattended or orchestrated turns, and it deletes the highest-frequency manual ritual (four hand-steps, every merit-bearing turn).
Downsides
Priciest item here (the verifier's cost flag): orchestrating python diagnostics from the Rust runner, a pre-register schema migration, and hash plumbing — for gates that have run ~15–20 times total. A leaner v1 (diagnose wrapper + verdict file, guardrail later) captures most of the value; per-lever diagnostic scripts still need authoring each time.

Head-relative re-audit sweep: knockout the KEEPs, resurrect the REVERTs

axis: lever-queue-meta Confidence 70% Complexity Medium

Description: Every verdict in the ledger is conditional on the baseline it was judged at — and the baseline has moved a long way. Run one pre-registered offline sweep in two directions. Knockout: ablate each kept lever one-at-a-time against v30 (genetics-style), flagging any lever whose removal doesn't degrade RoR as absorbed/stale. Resurrection: re-flip the REVERTed levers (RVOL, entry-cutoff, OR-width sanity) on v30 under the current size-invariant RoR crux — they were judged at v16 under the old expectancy metric, before four kept levers reshaped which trades carry risk. Requires a sanctioned read-only turn ablate mode: a 1.0→0.0 ablation is a 100% relative change, which the 0.5 proposal-bounds cap correctly refuses on the governed path (verified mathematically). One sweep, three artifacts: possible new KEEP or stale-KEEP retirement, the replay corpus for benchmarking future procedure changes, and metric vectors for a frontier of near-miss variants.

Basis
direct: "Baseline stays v16" verified verbatim at TURN-LOG.md:610 (RVOL's death certificate, signed four kept levers and one metric redesign ago); sentinel architecture verified ("the lever's code default stays the 0.0 sentinel; the head arms it"); no ablate mode exists in research.rs (verified by grep), and the bounds-cap math blocking 1.0→0.0 was verified in proposal_bounds.rs. external: gene-knockout panels / epistasis; AutoAlpha warm-starting from prior candidates.
Rationale
The KEEP set is the loop's accumulated capital and nothing ever re-audits it; the REVERT pile contains levers judged under a metric that no longer exists. Both directions test the same methodological gap — verdicts don't age gracefully — and the sweep's by-products (replay corpus, frontier) are exactly what ideas 1 and 3 need to version procedures safely.
Downsides
Every leg is a trial — run it after idea 2's accounting exists or it worsens the multiple-testing exposure it could otherwise help diagnose. Needs the turn ablate mode built with the read-only/never-head-moving constraint enforced, not assumed.

Runner seam hardening: stale-binary refusal + native version bump

axis: runner-teacher-seam Confidence 90% Complexity Low

Description: Delete the two most-scarred manual seams. (a) Stale-binary refusal: strategy_code_hash() already hashes orb.rs at compile time via include_str! — embed it as a build-id and have turn() refuse to run when the binary's hash doesn't match the source tree, replacing the human ritual of strings <bin> | grep -c <param>. (b) Native turn --code-bump: a first-class version-only-bump path for code turns, retiring the seed-manifest-and-rerun workaround and handling the multi-param companion-field gotcha automatically.

Basis
direct: the stale-binary gotcha bit twice on record (2026-07-12 close-confirm, 2026-07-15 ratio-ATR — both memory entries verified verbatim); strategy_code_hash() / ORB_SOURCE verified at manifest.rs:105-107; the no-version-only-bump gap is a documented open seam (docs/solutions/workflow-issues/code-turn-rebaseline-run-via-manifest-seed-and-rerun.md, confirmed on disk), and the runner already carries a refusal guard (KTD-5 expect_version) bolted onto the workaround it doesn't natively support.
Rationale
A stale binary doesn't error — it silently backtests the old strategy and produces a real-looking, wrong verdict: the worst failure mode a research loop can have, and it has already happened twice despite being documented. These are the cheapest, highest-confidence wins on the list, and both are hard prerequisites for any unattended operation.
Downsides
Individually small enough to feel unglamorous; the risk is doing them "later" a third time. No architectural payoff by themselves — they remove traps rather than add capability.

Prediction-calibration ledger + triage-lever skill

axis: gate-mechanization Confidence 70% Complexity Low

Description: The loop already makes falsifiable pre-registered predictions every turn — it just never grades itself. Score each one against its outcome (weather-forecasting's Brier-score discipline): Phase-A predicted a 57/167 bind and the flip delivered exactly 57/167 (hit); the RVOL diagnostic predicted its revert up front (hit); equity-compounding was expected INERT and read DUAL GO (miss). Freeze the diagnostic-first probe pattern as a triage-lever skill (input: candidate spec; output: PREDICT-KEEP/PREDICT-INERT/PREDICT-REVERT + frozen evidence) and log every prediction. Once the curve shows Phase-A revert-predictions are calibrated, a predicted revert can skip the build — meta-policy set by measured skill, not vibes.

Basis
direct: the 57/167 exact-hit verified at TURN-LOG.md:15 and :56; "Diagnostic-first — predicted the revert up front" verified in the RVOL entry; the equity INERT miss recorded in memory. external: forecast-verification culture (Brier/Murphy skill scores); NAS learning-curve extrapolation (predict outcomes from candidate features before full evaluation).
Rationale
This is the purest Level-6 move available: it doesn't add a gate, it measures the gates' predictive skill and uses that to decide when the expensive phase is worth running. The raw material is already frozen in PRE-REGISTER files — only the scoring loop is missing. It also generates exactly the data any future earned-autonomy scheme would need.
Downsides
Only a handful of scored predictions exist today, so the calibration curve is decoration for a while — the near-term value is the discipline (every probe states a prediction) and the skill extraction, not the curve. Skipping builds on predicted reverts must wait for real sample size.
