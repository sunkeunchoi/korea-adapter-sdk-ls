The picture

What right-censoring is

A measurement is right-censored when the recording process stops at a known bound before the true value is reached, so what lands in the data is the bound — and the only honest reading is true value ≥ bound. The canonical case is survival analysis: a five-year study ends and a patient is still alive, so their survival time is recorded as "5 years, censored" — they lived at least five years, not exactly five. The defining feature is that the cutoff comes from the measuring apparatus, not the phenomenon.

Why this lab manufactures it, structurally

In the ORB backtest, the thing that measures MFE and the thing that ends the trade are the same mechanism. mfe_r tracks high_water from entry — but the fixed profit target exits the trade the moment price reaches entry + profit_target_r · R. So every target-exit trade's MFE is clipped at the run's own profit_target_r (give or take intra-bar overshoot on the triggering bar). The distribution is not sampled from "how far winners run"; it is sampled from "how far winners run, through a window that closes at the current setting."

Below the target the two distributions agree almost exactly (p50, p70) — same entries, same market. Above it they diverge: v9's p75/p90 are pinned at its own 1.0 bound, while v10's higher window reveals real mass at 1.15 and 1.52 that v9 structurally could not record. The pinned tail is the censoring artifact; the divergence is the previously-unobservable region becoming visible.

The trap it prevented in turn 9

Turn 9's rule for picking the next profit target was "p70 of positive MFE, rounded to 0.05." Run that on v9 and you get 1.00 — the current setting echoed back, because the percentile sits exactly where the exit rule pins it. It looks like evidence ("the data says 1.0 is optimal!") but carries zero information: any target value would nominate itself by the same mechanism. The plan review caught this before execution: the leg-2 candidate had to come from the v10 run, whose 1.5 window leaves the 1.0–1.5 region observable — and that run produced a genuine candidate (p70 = 1.0476 → 1.05).

The report doesn't rely on the operator remembering this. The verdict is mechanical, in runner/report.rs: 

// A candidate pinned at the source target is the truncation echoing
// back, not information. Checked BEFORE the governance band — a
// censored candidate is uninformative regardless of band.
let verdict = if (candidate - profit_target_r).abs() <= CANDIDATE_STEP + 1e-9 {
    CandidateVerdict::RightCensored
} else if candidate < band.0 - 1e-9 || candidate > band.1 + 1e-9 {
    CandidateVerdict::OutOfBand
} else {
    CandidateVerdict::Runnable
};

Two supporting habits ride along: every report prints the source run's own profit_target_r and target-exit share next to the percentiles (so the truncation is visible in every future read, not rediscovered), and the tolerance is one rounding step — mfe_r can legitimately overshoot the target slightly within the triggering bar (high_water updates before the exit fires; v9's p90 is 1.05), so exact equality would under-detect.

The general lesson: when a system's control setting also terminates its own measurement, the recorded optimum will gravitate toward the current setting. Ask "could this statistic have come out any other way given the rule that recorded it?" before treating it as evidence. Other places the shape appears: timeout tuning from latency logs that the timeout itself truncates; retry budgets tuned from attempt counts capped by the budget; cache TTLs derived from observed entry lifetimes the TTL evicts.

What statisticians do about it (and what we did instead)

The proper toolkit treats a censored observation as the inequality it is. Survival analysis (Kaplan–Meier estimation, and regression models built on it) estimates the distribution using "≥ x" observations without discarding them or pretending they equal x — each censored point removes itself from the at-risk pool without registering an event. The lab's report takes the cheap, honest alternative: it doesn't estimate the uncensored distribution, it flags and refuses — a pinned candidate is declared RightCensored and a further sweep leg proceeds only by explicit operator override. Right-sized here because the decision needed is "is this candidate informative?", not "what is the true tail shape?" — and turn 9 got the informative candidate for free from the other leg's differently-censored window.

Where the concept does not apply

  • Fully observed quantities. Stop distances, entry slippage, opening-range width — nothing clips their recording. Treating them as censored would discard real data for no reason.
  • Missing data is not censoring. The 82 sizing-rejected breakouts have no MFE at all (no trade existed). Censoring means a partial observation with a known bound; absence is just absence — the report counts orphans separately rather than folding them in.
  • Left-truncation is a different animal. If trades below some MFE never entered the dataset at all (e.g., only logging exits above a threshold), the sample itself is biased — no per-observation bound can fix that, and the flag-and-refuse pattern doesn't transfer.
