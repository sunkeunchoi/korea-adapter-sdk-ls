1. 한 줄 결론

페이퍼 트레이딩은 코드 결함이 아니라 거버넌스 체인에 막혀 있습니다. 페이퍼 세션(lab-live --mount)은 인증된 헤드(certified head)가 있어야 열리는데, 현재 열린 전략 리니지가 없습니다. ORB 리니지는 2026-08-10에 탐지 불가능성 판정으로 CLOSED되었고, 후속 리니지 daily-resolution-v1은 2026-08-15에 동결되었지만 의도적으로 개방되지 않았습니다. 개방은 KRX/Koscom 라이선스 데이터 조달 판정(procurement verdict) 뒤로 미뤄져 있고, 그 조달 아크의 첫 단계는 오퍼레이터만 할 수 있는 샘플 지출 상한 동결입니다. 이 첫 단계는 어떤 외부 요인에도 막혀 있지 않습니다.

즉 "지금 당장 페이퍼를 돌리려면 무엇이 필요한가"의 답은 하나의 버그가 아니라 아래 8단계 의존 사슬입니다. 사슬의 맨 끝(8번)이 오늘 오퍼레이터가 손댈 수 있는 유일한 지점입니다.

2. 블로커 의존 사슬

위에서 아래로 "A를 하려면 B가 필요하다"의 순서입니다. 번호가 클수록 근본 원인에 가깝습니다.

  1. 페이퍼 세션 실행 — lab-live --genesis → --dispatch → --mount, 종료 코드 계약 0/66/71/72/77. 필요 조건: 유효한(green) dispatch. 사다리(ladder)는 2026-07-31에 stand-down 상태로 기록되어 어떤 genesis dispatch도 재등록 전에는 금지됩니다.
  2. 사다리 재등록 (prereg v3+) — 밴드를 새 헤드의 청산 거래 분포에서 Protective 공식으로 재도출, lab/tests/prereg_derivation.rs 확장, RUNG1-PREFLIGHT.md 3단계 리터럴 이동을 같은 커밋에서. 필요 조건: 동결 마진을 통과한 인증된 헤드. 현재 config/preregistration.json은 v2 그대로이며 편집은 프로토콜 위반입니다.
  3. 인증된 헤드 — 후속 리니지의 홀드아웃 판정이 lineage-preregistration.json의 verdict.hurdle(+0.0361 net RoR)을 통과해야 합니다. 필요 조건: 열린 리니지에서 턴 1이 실행되어야 함. 큐 항목 rung1-ladder-reentry-successor-margin-head가 이 조건으로 PARKED.
  4. 열린 리니지 없음 — TURN-LOG 표준 블록: currently open: NONE. ORB는 CLOSED (임계 +0.128605 vs 최선의 허용 가능 net RoR −0.0006). 데이터를 사도 재개 불가(CONCEPTS.md Lineage closure 규칙). 구조적 원인: LS 게이트웨이가 분봉을 약 359일 롤링 윈도로만 제공 → 도달 가능 세션 240 vs 필요 3,499.
  5. daily-resolution-v1 개방 보류 — 동결(해시 0ecd9d11…)은 완료, 개방은 별도 커밋. 2026-08-27 계획의 사용자 결정: "조달 견적이 상한을 통과할 때까지 동결 상태로 미개방 유지". 이 동결은 조달이 실패했을 때의 유일한 대안(fallback)이라 먼저 철회하지 않습니다. 필요 조건: arc-procurement-verdict 종결. 개방 자체는 pre-turn admissibility re-check 통과 후 TURN-LOG 표준 블록의 기계적 편집.
  6. 조달 판정 — 생산 견적을 동결 상한과 하나의 합계로 비교해 터미널을 기록. 상한 초과면 아크 stand-down, 아무것도 인제스트하지 않음. 필요 조건: 생산 요청 발송(arc-production-ask-ceiling-and-send) ← 샘플 수용 테스트(arc-sample-acceptance-tests) ← 검증 샘플 요청 발송.
  7. 검증 샘플 요청 발송 priority — arc-send-verifying-sample-ask. 요청 패키지 Part B/C/D는 작성 완료, 미발송. 오퍼레이터가 서명·발송해야 하며 외부 리드타임은 무제한. 필요 조건: 샘플 상한이 동결되고 해시로 인용될 것 (R6: 상한 없이 유료 행위 금지).
  8. 샘플 지출 상한 동결 오늘 가능 — arc-sample-spend-ceiling-freeze. KRX 공시 정가로 상한을 정하고 config/SAMPLE-MARGIN.md + sample-margin.json 미러에 기록, 네 가지 조달 터미널(정상 회신 / 부분 회신 / 무응답 / 상한 초과 견적)도 함께 기록. 큐 원문: "A2의 절반은 완료 — 이것은 오퍼레이터의 행위이며 어떤 외부 요인도 이를 막지 않는다."

병렬 블로커 하나가 더 있습니다. 사슬과 별개로, 페이퍼 세션을 실제로 의미 있게 돌리려면 큐 항목 orb-cost-artifact-hash-and-head-identity(U5+U6+U7)가 먼저 닫혀야 합니다. 3절 B4 참조. 이것도 오퍼레이터가 보유한 데이터 홈에서만 풀 수 있습니다.

3. 블로커 상세

B1. ORB 리니지 CLOSED — 구조적, 재개 불가 근본 원인

  • 무엇: 2026-08-10 arm C stand-down이 2026-08-11에 CONCEPTS.md의 사전 등록된 Lineage-closure 규칙에 결합되었습니다. 동결 샘플 마진의 임계값을 도달 가능 샘플 상한(237 세션)에서 평가하면 +0.128605, 리니지가 낸 최선의 허용 가능 net RoR은 v35의 −0.0006. 조건 성립, CLOSED.
  • 왜: LS 게이트웨이는 분봉을 약 359일 롤링 윈도로만 제공합니다(2026-07-09 358일, 2026-08-10 359일로 재확인). 인트라데이 리니지의 도달 가능 세션은 지출과 무관하게 약 240개인데, 2026-08-06 표본 충분성 턴은 v35의 엣지(+0.0284 R)가 탐지 하한보다 약 9배 작고 3,499 세션이 필요하다고 측정했습니다. 2026-08-07 paired-power 턴은 6개 레버 off-flip 중 0개가 귀속 가능함을 확인했습니다.
  • 중요: 폐쇄는 수익성이 아니라 탐지 가능성에 대한 진술이며, 데이터를 구매해도 재개되지 않습니다. 더 큰 가설 효과 크기이거나 더 깊은 공급을 가진 해상도(일봉)만이 답을 바꿉니다. v32의 0.1876, v34의 0.0398은 각각 구 카탈로그·비용 미반영이라 허용되지 않습니다.
  • 이전 단계: 2026-07-31 거래비용 모델(매도세 20bp + 수수료 1.5bp/측)을 장착하자 헤드가 순손실(net RoR −0.0006, 111 거래)로 재측정되어 rung-1 사다리가 stand-down되었습니다(PR #238). 동결 v2 밴드 [−148k, +266k]는 비용 미반영 분포에서 나온 것이라 헤드가 기대상 통과할 수 없는 밴드였습니다.

B2. 후속 리니지 daily-resolution-v1 동결됨, 미개방 사용자 결정

  • 무엇: 2026-08-15 P6에서 동결(PR #287, 콘텐츠 해시 0ecd9d11…). S_max 2,460 세션(2016-08-01 ~ 2026-08-12), 분할 837 / 1,566 / 57, N_max = 1(홀드아웃 판정 단 1회), 허들 +0.0361, 16세션 보유, m = 8, 동시 128 포지션.
  • 왜 미개방: 두 가지 게이트가 겹칩니다. (1) 설계상 개방은 동결과 별도 커밋이며 pre-turn admissibility re-check(사양 윈도에서 이 리니지 자체의 ICC·세션당 거래·참여율을 재측정)가 통과해야 합니다. 이 체크는 "개방 거부"가 가능해야 하므로 동결이 슬롯을 먼저 소비하지 않습니다. (2) 2026-08-27 검증 아크 계획이 사용자 지시로 "견적이 상한을 통과할 때까지 동결 유지"를 결정했습니다. 동결은 조달이 실패할 때 남는 유일한 전략 프로그램이라 미리 철회하지 않습니다.
  • 코드 준비 상태: 개방에 필요한 코드 선행 조건은 모두 완료되었습니다. P3 일봉 카탈로그 2016 플로어 풀(352/352, 741,580 바, PR #276), P4 pit-universe 걸음(PR #274), P7 다중 세션 보유 백테스트 경로(2026-08-16), 보유 종목 결측 바 fail-closed(PR #304). 실행 바이너리 lab-backtest-daily가 존재합니다.
  • 주의: 턴 1이 사실상 이 리니지의 유일한 기회입니다. 업그레이드 턴 하나당 약 6.4년의 전진 누적이 필요합니다.

B4. 라이선스 독립 꼬리 결함 — U5+U6+U7, 오퍼레이터의 v35 베이스라인 필요 페이퍼 세션 직접 관련

  • 모순의 정체: config/preregistration.json의 rung0_requalification은 "LS_TRADING_ENV=paper에서 최소 3회의 clean 페이퍼 세션"을 요구합니다. 그런데 is_clean_session(lab/src/dispatch/ladder.rs:397)은 dispatch 링크의 trading_env가 live가 아니면 무조건 거부하고, 페이퍼 마운트는 trading_env: "paper"를 기록합니다. 따라서 페이퍼 세션은 절대 clean으로 집계될 수 없고, 카운터는 1에 도달할 수 없습니다. 이 결함은 오퍼레이터가 아크의 최종 세션을 돌리려는 순간까지 보이지 않습니다.
  • 계획된 수정: 계획 2026-08-27-1453의 R11: is_clean_session과 구별되는 페이퍼 레인 청결 술어를 만들고, 그것이 갖춰지기 전엔 기존 REREGISTER_REFUSED 경로로 거부. 동결 텍스트는 그대로 둡니다(수정이 아니라 별도 술어).
  • 왜 막혔나: U5(비용 아티팩트 해시)는 lab/src/strategy/orb.rs를 편집해야 하는데 strategy_code_hash가 그 파일의 sha256이라 문서화된 헤드 다이제스트 7571abef…가 이동합니다.   • 순서 제약(KTD12): U5 → U6 → U7이 어떤 페이퍼 세션보다 먼저 착지해야 합니다. 페이퍼 세션이 쌓인 뒤 헤드 정체성을 옮기면 그 세션들이 무효화되어 두 번 비용을 치릅니다.
  • 풀리는 조건: (a) 오퍼레이터가 v35 아티팩트가 있는 데이터 홈에서 U5 재베이스라인을 실행해 정확한 일치를 확인, 또는 (b) 헤드 정체성 이동을 자체 거버넌스 행위로 기록하기로 결정. U8(produce_report 생산 호출자)은 완료(389197d).

4. 페이퍼 랩에 대한 오해 정리

페이퍼 레인은 자격을 부여하는 단계가 아니라 반증 기회입니다. LS_TRADING_ENV=paper는 LanePosture::Paper("rung informational")로 해석되어 사다리 증거를 절대 쌓지 못합니다. 리니지 사전 등록의 prospective_paper_stage 게이트도 같은 말을 합니다. 홀드아웃 판정을 통과한 전략이 페이퍼 레인에서 전진 실행되며 실현 행동을 등록된 효과와 비교하는 것이 "페이퍼 트레이딩"의 이 프로젝트 내 정의입니다. 즉 페이퍼 트레이딩은 인증된 헤드의 뒤에 오지, 인증을 만들어 내는 수단이 아닙니다.

2026-07-28 ~ 07-31의 아침 체인 실행(75/75 GO)은 데이터 인제스트와 마운트 준비였고, 마운트는 설계상 stand-down되어 있었습니다. "페이퍼 세션을 돌렸다"는 기록은 저장소에 없습니다.
